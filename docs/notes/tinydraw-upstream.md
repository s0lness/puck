# A note for aliceisjustplaying/tinydraw (not sent)

`scripts/build-puck-wasm` exits 1 on GitHub's `ubuntu-latest` runner because that image carries `cmake` but not `ninja`, so `command -v ninja` fails before the `cmake -G Ninja` invocation ever runs; installing `ninja-build` (apt) or `ninja` (a GitHub Actions setup step) in the workflow that calls this script would close that gap. On a Windows host the script already has everything it needs once `WASI_CXX` names a real `clang++` (the `if [[ -n "${WASI_CXX:-}" ]]` branch skips the uname switch entirely), so no code change is required there, but an explicit `MINGW*|MSYS*` (or a broader `*`) case in that `uname -s`:`uname -m` switch, naming the Windows wasi-sdk asset and its checksum the same way the four existing cases do, would let the script fetch its own toolchain instead of refusing the host outright. Separately, and unrelated to either host: `bundle.json`'s `build.commit` (`000de0aa7461`) has fallen behind `puck/frames`, which a handful of commits since (edge-drawing and live-stroke fixes) have regenerated without the pin following, so the bundle at `HEAD` is not currently self-consistent; pinning to an earlier commit where the two still agree is what this repository's own `registry.json` does today.
